# 跨文化表达实验室设计规格

## 1. 背景

Termbase 第一阶段已经完成多语术语知识核心和公共门户，用户可以检索术语、查看译文、来源、语境、文化说明、关系和专题。但当前交互仍以知识阅读为主，尚未把知识库转化为可操作的跨文化表达研究流程。

跨文化表达实验室将术语知识、传播场景和 DeepSeek 的生成能力组合为结构化研究工具。它不是自由聊天窗口，也不是通用机器翻译器，而是一个要求用户先选择知识依据、再生成和比较英语表达方案的“人机协同”工作流。

## 2. 目标

第一版交付以下能力：

1. 用户从已发布术语中选择 1–5 个知识依据。
2. 用户输入中文表达，并选择目标受众、传播场景、表达风格和英语区域。
3. 后端读取所选术语的译法、来源、语境和文化说明，构造编号知识包。
4. DeepSeek 返回结构化的推荐译文、备选方案、术语采用情况、文化风险、引用依据和人工复核提示。
5. 后端验证模型结构和引用编号后再向前端返回结果。
6. 用户可以比较、复制并导出 Markdown 或 JSON 研究记录。

## 3. 非目标

第一版明确不实现：

- 任意语言生成。首发目标语言仅为英语。
- 自由聊天或多轮对话。
- 匿名保存研究案例到数据库。
- 登录、角色、提交、教师审核和正式发布。
- 第二次模型调用形成的“生成—批评—修订”链路。
- 向量数据库、语义检索、智能体框架或微服务。
- 将 AI 输出宣称为官方、权威或已经人工审核的结论。

后续研究工作台完成后，再增加案例保存、复核和成果沉淀；其他目标语言在对应术语数据与来源达到可用质量后逐步开放。

## 4. 核心原则

### 4.1 知识库优先

每次生成必须关联 1–5 个已发布术语。模型只能使用本次知识包中的术语、译法和来源编号。没有知识依据时不允许提交。

### 4.2 结构化而非聊天化

页面以研究任务和对照报告组织，不使用聊天气泡。模型输出必须符合固定模式，后端校验通过后才展示。

### 4.3 人工判断优先

所有结果都显示“AI 生成、尚未人工复核”。系统提供选择理由、风险和局限，不替用户作最终学术判断。

### 4.4 数据最小化

第一版不保存输入和生成结果。结果只保留在当前前端会话，用户可主动复制或导出。

### 4.5 简单可扩展

第一版单次调用 DeepSeek，但生成服务边界允许未来增加二次审校。请求中保留稳定的目标语言字段，当前只接受英语。

## 5. 用户流程

### 5.1 建立知识依据

用户在 `/lab` 页面搜索并选择术语。选择数量最少 1 个、最多 5 个。候选术语只来自已发布内容，每项展示：

- 中文首选名称
- 推荐英文译法（如有）
- 术语层级
- 文化分类
- 数据质量标识
- 可展开的来源和文化说明摘要

页面右侧或移动端下方形成“本次分析知识包”，允许移除已选术语。

### 5.2 设置传播任务

用户填写 10–1000 个中文字符，并选择以下固定枚举：

- 目标受众：学术研究、国际媒体、海外青年、普通公众
- 使用场景：学术论文、政策文本、新闻传播、文化展示、社交媒体
- 表达风格：正式、解释性、简洁、易懂
- 英语区域：通用英语、英式英语、美式英语

提交前显示知识摘要，例如：“依据 3 个术语、5 条既有译法和 4 个来源，为海外青年文化展示场景生成英语表达。”

### 5.3 生成与等待

第一版使用普通 POST 请求，不展示未经验证的流式片段。等待期间按顺序显示：

1. 整理知识依据
2. 生成表达方案
3. 校验引用和输出结构

这些阶段是用户界面状态说明，不伪造后端已经完成的精确进度百分比。

### 5.4 查看与比较

结果按研究报告展示：

1. 首选译文
2. 备选表达对照
3. 方案差异和选择理由
4. 术语采用情况
5. 跨文化风险
6. 表达策略
7. 引用依据
8. 局限和人工复核优先级

用户可以返回修改条件、重新生成、复制首选译文、复制完整报告、导出 Markdown 和下载 JSON。

## 6. 页面与组件

新增路由：

```text
/lab
```

页面组件建议拆分为：

```text
features/expression-lab/
  ExpressionLabPage.tsx
  TermSelector.tsx
  KnowledgePack.tsx
  CommunicationTaskForm.tsx
  GenerationStatus.tsx
  ExpressionReport.tsx
  AlternativeComparison.tsx
  CulturalRiskPanel.tsx
  ReferenceList.tsx
  exportExpressionReport.ts
  expression-lab.css
```

组件职责：

- `TermSelector`：搜索和选择已发布术语。
- `KnowledgePack`：展示本次可供模型使用的知识依据。
- `CommunicationTaskForm`：管理中文输入和固定枚举。
- `GenerationStatus`：展示等待阶段和取消/重试入口。
- `ExpressionReport`：组织通过验证的完整结果。
- `AlternativeComparison`：并列比较首选与备选表达。
- `CulturalRiskPanel`：按风险级别呈现问题和建议。
- `ReferenceList`：只展示后端验证并重新填充的真实来源。
- `exportExpressionReport`：从前端已验证响应生成 Markdown 和 JSON。

页面沿用现有深海军蓝、克制朱砂、暖白和浅灰设计令牌，保持人文研究平台风格。移动端将知识包和表单改为纵向排列，结果对照卡片可横向滚动或堆叠。

## 7. API 设计

### 7.1 分析接口

```text
POST /api/v1/expression-lab/analyze
Content-Type: application/json
```

请求：

```json
{
  "term_ids": [12, 35],
  "source_text": "需要外译的中文表达",
  "target_language": "en",
  "audience": "overseas_youth",
  "scenario": "cultural_exhibition",
  "style": "explanatory",
  "locale": "general_english"
}
```

约束：

- `term_ids` 去重后为 1–5 个正整数。
- 所有术语必须存在且状态为 `published`。
- `source_text` 去除首尾空白后为 10–1000 个字符。
- `target_language` 第一版只接受 `en`。
- 其余字段必须属于服务器定义的枚举。
- 请求体设置合理的最大字节限制。

成功响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "request_id": "opaque-id",
    "input_summary": {},
    "knowledge_summary": {},
    "report": {},
    "generated_at": "ISO-8601 timestamp",
    "review_status": "ai_unreviewed",
    "warnings": []
  }
}
```

错误使用现有稳定错误信封：

```json
{
  "code": 400,
  "message": "可理解的错误说明",
  "data": null
}
```

建议状态码：

- `400`：字段格式或枚举错误
- `404`：术语不存在或未发布
- `413`：请求体或原文过大
- `422`：模型输出无法通过结构校验
- `429`：调用频率过高
- `502`：模型供应商返回不可用结果
- `503`：模型服务暂时不可用或超时

## 8. 知识包构造

后端新增独立服务，根据所选术语一次性加载：

- 术语基本信息和数据质量
- 英语译法及译法语境
- 来源与证据摘录
- 概念语境
- 跨文化说明
- 与当前表达有直接帮助的术语关系

每个可引用对象分配稳定的本次请求编号，例如：

```text
TERM-1
TRANSLATION-1
SOURCE-1
CONTEXT-1
NOTE-1
```

知识包限制总字符数，优先级依次为推荐英语译法、直接证据、文化说明、语境、关系。裁剪时记录警告，但不改变数据库内容。

模型只看到为本次任务整理后的必要字段，不接收数据库连接信息、内部路径、API Key或未发布内容。

## 9. DeepSeek 生成服务

新增专用表达生成服务，不直接复用旧聊天路由的自由对话提示词。服务职责：

1. 接收已验证的传播任务和知识包。
2. 构建系统规则、知识区和被明确引用包裹的用户原文。
3. 调用当前 DeepSeek OpenAI 兼容客户端。
4. 解析结构化 JSON。
5. 使用服务端模式进行字段、枚举、长度和数量验证。
6. 结构错误时最多进行一次格式修复重试。
7. 返回内部领域对象，不直接返回供应商响应。

用户原文始终被标记为“待翻译内容”，其中出现的命令、角色声明或系统提示不得覆盖系统规则。日志只记录请求 ID、耗时、状态和非敏感错误类别，不记录完整原文、知识包、供应商原始响应或密钥。

## 10. 输出模式

报告固定包含：

```json
{
  "recommended": {
    "text": "Recommended expression",
    "rationale": "选择理由",
    "strategy": ["explanatory_translation"]
  },
  "alternatives": [
    {
      "text": "Alternative expression",
      "best_for": "适用场景",
      "tradeoff": "相对取舍"
    }
  ],
  "term_usage": [
    {
      "term_id": 12,
      "translation_id": 31,
      "adopted_translation": "harmony in diversity",
      "explanation": "采用原因"
    }
  ],
  "cultural_risks": [
    {
      "level": "medium",
      "issue": "风险说明",
      "recommendation": "处理建议"
    }
  ],
  "references": [
    {
      "source_id": 8,
      "usage": "引用用途"
    }
  ],
  "limitations": ["需要英语母语审校"],
  "review_priority": "medium"
}
```

限制：

- 推荐译文恰好 1 个。
- 备选方案为 1–3 个且不得与首选完全相同。
- 风险级别只允许 `low`、`medium`、`high`。
- 复核优先级只允许 `low`、`medium`、`high`。
- `term_id`、`translation_id` 和 `source_id` 必须属于本次知识包。
- 不接受模型提供的来源标题、机构或 URL；后端根据合法编号重新填充。
- 非法引用被移除，并在 `warnings` 中说明。
- 任何成功响应都由后端设置 `review_status: ai_unreviewed`。
- 不展示没有客观依据的百分比置信度。

## 11. 安全和成本控制

- API Key继续只从被 Git 忽略的 `term-backend/.env` 读取。
- 分析接口按客户端 IP 限流，默认每分钟最多 5 次。
- 请求体、原文长度、术语数量和知识包长度均受限制。
- 只允许服务器定义的枚举，拒绝任意模型名、提示词或系统规则参数。
- 超时和供应商异常不向浏览器返回内部错误详情。
- 成功和失败日志都不得包含 API Key。
- 前端不能直接请求 DeepSeek。
- 返回 Markdown 前按纯文本处理模型字段，不执行模型生成的 HTML。
- 导出文件名和内容由可信模板生成，避免用户输入控制路径。

限流采用可替换边界。单机开发可使用进程内存储；部署到多实例环境前必须切换共享存储，文档中明确该限制。

## 12. 错误处理与降级

- 无术语或字段错误：在提交前和 API 层同时拦截。
- 术语在选择后被取消发布：返回 404，并提示重新选择知识依据。
- DeepSeek 超时或不可用：保留用户表单和已选术语，提供重试。
- 返回非 JSON 或字段缺失：进行一次仅限格式修复的重试；再次失败返回 422。
- 模型虚构引用：删除引用、保留其他合法内容，并显示警告。
- 所有引用均非法：报告可以返回，但引用区显示“未能建立有效来源关联”，并提高人工复核优先级。
- 前端刷新：结果丢失，符合第一版不持久化设计。

## 13. 导出

### 13.1 Markdown

Markdown文件包含：

- 任务条件
- 中文原文
- 首选和备选译文
- 术语采用情况
- 文化风险
- 引用来源
- 局限
- 生成时间
- AI 未复核声明

### 13.2 JSON

JSON导出保存后端成功响应中的非敏感 `data` 对象，便于后续研究工作台导入。它不包含 API Key、内部提示词、供应商原始响应和服务器日志字段。

## 14. 测试策略

### 14.1 后端单元和接口测试

- 请求枚举、术语数量和原文长度校验。
- 只允许读取已发布术语。
- 知识包编号稳定且不包含未发布数据。
- 正常结构化生成和字段验证。
- 非 JSON、缺字段、超长字段和非法枚举。
- 格式修复最多重试一次。
- 虚构术语、译文和来源编号被删除。
- 供应商超时、限流和内部错误正确映射且不泄密。
- API响应始终包含 `ai_unreviewed`。
- IP限流达到阈值后返回429。

### 14.2 前端测试

- 搜索、选择和移除术语。
- 1–5个术语限制。
- 表单枚举和长度校验。
- 请求载荷与API契约一致。
- 加载阶段、失败、重试和结果展示。
- 首选与备选对照、风险等级和引用链接。
- 未复核提示始终可见。
- Markdown与JSON导出内容正确，不执行HTML。
- 移动端关键交互和键盘可访问性。

### 14.3 回归测试

- 现有后端测试、DeepSeek SSE接口和公共术语API继续通过。
- 现有首页、探索页和知识档案页测试继续通过。
- 前端生产构建和lint无新增错误。
- 跟踪文件密钥扫描保持干净。

## 15. 验收标准

功能完成必须满足：

1. `/lab`可以完成选择术语、填写任务、生成、比较和导出全流程。
2. 未选择术语不能提交。
3. 第一版只接受英语目标语言。
4. 模型结果使用固定结构，非法结构不会直接展示。
5. 所有展示来源由后端根据合法编号填充。
6. 任意成功结果都明显标记为AI未复核。
7. 不向数据库保存用户原文和分析结果。
8. 错误不清空表单，不泄露密钥或供应商内部细节。
9. 公开接口具备基本频率限制。
10. 后端、前端、构建、迁移回归和密钥扫描全部通过。

## 16. 后续演进

按顺序考虑：

1. 增加“已有译文评估”模式。
2. 增加第二次跨文化审校调用。
3. 接入研究工作台，保存、修改、提交和复核案例。
4. 在数据充分后开放法语、西班牙语、俄语和阿拉伯语。
5. 对人工选用结果建立评测集，比较模型建议与专家修订差异。
