# 术语聚合与淮河文脉视觉改版设计

## 目标

本次改版解决三个直接影响使用的问题：同名术语在检索结果中重复出现，儿童释义与使用场景的语义边界不清，以及淮河文脉图谱与 AI 助手缺少鲜明、统一的文化视觉表达。完成后，检索结果以一个主词条承载多个文化义项，详情页明确区分文化内涵、使用场景和儿童友好释义，淮河专题以真正的河流作为空间主线，AI 助手以轻量数字人物呈现。

## 设计原则

- 保留现有“新中式学术编辑部 + 数字人文”定位，不另起一套 UI 框架。
- 视觉升级依靠信息层级、图标、柔和立体感和动效，不堆叠无意义装饰。
- 不破坏历史数据，不自动删除或覆盖同名记录。
- 儿童释义属于适读版本，不属于使用场景。
- 每个术语保留一个主要层级；跨层信息通过术语关系表达。
- 动效尊重 `prefers-reduced-motion`，图标和颜色都不能成为唯一语义载体。

## 方案

### 主词条和文化义项

公共 API 对同名已发布术语建立非破坏性的“规范词条投影”。完全相同的中文首选名归入同一组，以编号最小的记录作为规范入口。组内每条具有非空且不同的文化内涵或定义时，形成一个文化义项；完全重复的内容只显示一次。此方式立即修复既有数据库中的重复检索结果，同时保留所有历史记录及其审核依据。

术语摘要新增：

- `interpretation_count`：去重后的文化义项数量。
- `record_count`：该规范词条下保留的历史记录数量。

术语详情新增 `interpretations`，每项包含编号、标题、解释、文化内涵、记录层级、文化分类和来源记录 ID。原有 `cultural_connotation` 保留兼容，但新界面以 `interpretations` 为展示来源。

分页、关键词、层级、文化分类和语言筛选都先作用于记录，再按名称聚合；只要组内任一记录满足筛选条件，该规范词条就出现一次。详情页从任一同名记录链接进入时，都返回同一规范词条投影。

### 检索结果

检索结果继续采用编辑式纵向列表，避免回到大面积空白的 PPT 卡片。每项增加统一 SVG 图标、主层级标记、一句定义、推荐译法，以及“含 N 个文化义项 / N 条来源 / N 种语言”信息。整行可点击，悬停仅做轻微抬升和底色变化。

### 术语详情

详情页顺序为：

1. 术语概览与主要层级。
2. 儿童友好释义，仅在儿童模式中显示，使用友好的风筝图标。
3. 多语译法。
4. 文化内涵，以 01、02、03 编号的纵向义项呈现。
5. 使用场景，永远排除 `children` 上下文。
6. 跨文化提示、来源证据、相关概念与专题。

同名记录出现不同层级时，头部只展示规范记录的主要层级；其他层级只在具体文化义项中作为“研究记录层级”保留，避免误导用户认为一个术语同时属于三层。

### 淮河文脉图谱

现有两条虚线改为分层 SVG 河流：宽底色描边形成河床，青蓝渐变主河道形成水体，半透明高光虚线产生缓慢流动效果。河道两侧标注寿县、淮南、蚌埠、凤阳四个地名。原有白芍、刘安等数据节点继续由专题数据驱动，并用人物、草木、地点、术语和文化五类内联 SVG 图标替代单字圆章。

节点使用轻量悬浮和景深阴影；关系线不使用纯黑色。移动端保留横向可读布局，减少节点尺寸。减少动效模式下关闭河流流光和节点漂浮。

### AI 数字人物

AI 悬浮入口改为一位抽象的“文脉数字研究员”：由内联 SVG 头像、发髻/头冠、面部和衣领构成。待机时进行轻微呼吸和眨眼，思考时出现柔和环形提示。数字人物只是入口视觉，不改变现有聊天请求、流式响应、键盘操作和可访问名称。

### 色彩与立体感

主色沿用墨青，补充淮水青蓝和青玉绿；背景保持暖宣纸色，强调色保留朱砂和古铜金。阴影分为浅层内容抬升和专题深色舞台两级，不使用高反差黑线或厚重玻璃拟态。

## 兼容与风险控制

- 公共 API 保留旧字段，新增字段为向后兼容扩展。
- 同名但确属不同概念的记录可能被聚合；界面保留不同义项、层级和来源记录 ID，使研究人员可识别，后续可通过别名或人工拆分机制处理。
- 聚合发生在公共读取服务，不改写管理员数据和历史表。
- 空文化内涵记录不会产生空白义项；若所有记录都为空，则用定义生成一个回退义项。
- 所有新增 SVG 为本地代码资产，不依赖外部图片或新运行时依赖。

## 验收标准

- 搜索“文化自信”只出现一个结果，并显示多个文化义项数量。
- 从任一同名记录进入详情都能看到同一组编号义项。
- 儿童释义不出现在“适用场景”列表中。
- 文化自信头部只显示一个主要层级，其他层级出现在对应研究义项中。
- 淮河图谱呈现连续河流、四个地名和现有重要人物/本草节点，且不再出现黑色连接线。
- AI 入口显示数字人物并保留原聊天功能和可访问名称。
- 后端测试、前端测试、前端 lint 与生产构建全部通过。
