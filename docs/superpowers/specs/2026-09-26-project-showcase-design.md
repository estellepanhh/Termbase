# 项目介绍与成果展示页设计规格

## 1. 目标与定位

在现有平台中新增正式的 `/about` 项目介绍与成果展示页，并将其加入桌面端和移动端主导航。页面首先服务项目评审、指导教师和答辩场景，同时保证普通公众无需专业背景也能理解。

它不是首页的重复版本，也不是单纯的“关于我们”。首页继续承担检索和功能分流；本页面集中回答四个问题：项目为什么建设、怎样建设、已经形成什么成果、下一步准备做什么。

页面突出外国语学院项目的语言研究、跨文化阐释、人机协同与知识积累。DeepSeek、React、Flask 等实现手段不作为核心成果宣传。所有成果数字必须来自数据库实时统计，不虚构团队信息、研究结论或成果规模。

## 2. 范围

本期包含：

- 双语项目成果页和主导航入口；
- 项目定位、研究缘起、建设方法、平台能力、创新点、阶段进展和项目说明；
- 只读公开成果概览接口；
- 术语、译名、已发布文化专题和已覆盖语种四项真实统计；
- 指向检索、表达实验室、文化专题和研究工作台的站内链接；
- 儿童模式、大字模式和移动端适配；
- 加载、接口失败和零数据状态；
- 后端接口测试、前端服务测试、页面测试和路由/导航测试。

本期不包含：

- 项目内容后台编辑器；
- 团队成员、指导教师姓名或未确认的立项编号；
- 论文、奖项等无法从当前系统核验的成果；
- 数据图表驾驶舱、复杂动画或新增第三方可视化依赖；
- 对现有首页、文化专题或工作台的结构性重做。

## 3. 信息架构

页面按以下顺序组织：

1. **项目封面**：项目名称、项目定位、简短说明和“查看建设成果”锚点按钮。
2. **研究缘起**：说明中国特色话语跨语传播中的概念解释、语境差异和依据追溯问题。
3. **建设方法**：以“术语采集 → 规范整理 → AI 辅助 → 人工审校 → 多语发布”展示术语生产闭环，并明确 AI 只提供辅助方案，最终判断由研究者完成。
4. **成果概览**：展示四项数据库实时统计。统计不可用时不显示伪造数字，改为统一的暂不可用提示和重试操作。
5. **平台能力**：介绍术语检索与档案、跨文化表达实验室、文化专题、研究工作台，各模块链接到现有页面。
6. **项目创新**：语言研究、文化阐释、人机协同、知识工程四项，使用克制的研究性表述。
7. **建设进展**：明确区分“已形成”和“持续建设”，只列当前仓库已经提供的能力及确定的下一阶段方向。
8. **项目说明**：说明项目属于大学生创新训练项目成果，保留后续补充团队与立项信息的位置，但不显示空白占位符。

中文和英文文案各自完整维护，不在同一段落中混排。儿童模式对研究缘起、闭环和创新点使用更直接的表达，但保留相同事实；大字模式只改变排版，不删减内容。

## 4. 后端架构与数据契约

新增公开、只读、无参数接口：

`GET /api/project/overview`

成功响应：

```json
{
  "code": 200,
  "data": {
    "term_count": 0,
    "translation_count": 0,
    "language_count": 0,
    "published_topic_count": 0
  }
}
```

统计规则：

- `term_count`：`kb_terms` 表记录总数；
- `translation_count`：`kb_translations` 表记录总数；
- `language_count`：`kb_translations` 中 `language_id` 的去重数量；
- `published_topic_count`：`kb_topics` 中状态为 `published` 的专题数量。

计数均为非负整数，空库返回零。接口不返回审核工作台状态、未发布专题、AI 配置或其他内部信息。

后端拆分为：

- `services/project_overview.py`：单一统计查询与序列化逻辑；
- `routes/project_overview.py`：HTTP 响应；
- 应用工厂注册新蓝图。

## 5. 前端组件与数据流

新功能位于 `src/features/about/`，避免继续使用 `src/pages/AboutPage.tsx` 中的旧式内联样式页面。

组件边界：

- `AboutPage.tsx`：页面编排、语言与阅读模式选择、数据加载状态；
- `ProjectHero.tsx`：封面区；
- `ResearchWorkflow.tsx`：五阶段术语生产闭环；
- `OutcomeOverview.tsx`：四项真实成果数据及状态反馈；
- `PlatformCapabilities.tsx`：现有模块说明和站内跳转；
- `aboutCopy.ts`：中英文普通模式与儿童模式文案；
- `about.css`：页面专属响应式样式。

新增 `ProjectOverview` 类型和 `getProjectOverview(): Promise<ProjectOverview>` 服务函数。页面挂载时请求一次数据；成功后渲染数字，失败后保留其余静态内容并提供重试按钮。组件卸载后不得写入状态。导航中的 `/about` 不再重定向，改为渲染新页面。

## 6. 视觉与响应式设计

视觉延续现有纸张色、靛蓝和朱红色设计语言，整体气质为“学术展陈 + 数字人文”。页面采用宽幅封面、纵向叙事和错落卡片，不使用企业化大屏、玻璃拟态、过量渐变或装饰动画。

- 桌面端：内容最大宽度与现有页面一致，成果卡片四列，平台能力两列，研究流程五段展开。
- 平板端：成果卡片两列，流程允许换行。
- 手机端：所有区域单列，研究流程改为清晰的纵向编号，触控链接保持足够点击区域。
- 大字模式：通过现有 `data-large-text` 机制继承全局字号，同时避免固定高度导致文本裁切。
- 儿童模式：通过现有 `ChildModeContext` 切换简明文案，不新增第二套路由。
- 无障碍：语义化 section/heading/list、锚点目标可聚焦、加载状态使用 `aria-live`，装饰元素不进入辅助技术阅读流。

## 7. 异常与边界处理

- 空数据库：四项成果均显示 `0`，不视为错误。
- 网络或后端失败：静态项目介绍照常可读；成果区显示错误说明和重试按钮。
- 重试期间：成果区显示加载状态并禁止重复触发。
- 切换语言：不重新请求统计，只替换界面文案。
- 切换儿童/大字模式：不重置请求结果和页面位置。
- 较长英文标题和数字：布局允许换行，不设置会截断内容的固定高度。

## 8. 测试与验收标准

后端测试覆盖：

- 含重复语种、已发布与未发布专题时的四项统计；
- 空数据库返回四个零；
- 响应只包含公开契约字段。

前端测试覆盖：

- 服务函数请求正确端点并解包响应；
- `/about` 可直接访问且导航链接存在；
- 成功状态渲染真实统计和四个功能入口；
- 加载、失败、重试与零数据状态；
- 中英文切换和儿童模式文案；
- 移动端导航中包含项目成果入口。

验收时运行后端完整测试、前端完整测试、TypeScript 构建和 lint。最终页面不得包含虚构姓名、虚构数字、暴露的 API 密钥或未确认成果。
